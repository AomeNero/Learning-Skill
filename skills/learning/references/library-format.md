# library/ 资料条目格式

`library/` 位于工作区根目录（与 `lessons/` 同级）。每条资料一个 MD 文件，命名 `0001-<dash-case-name>.md`，编号扫描现有最大加一。它们是知识库的**资料层**——researcher 摸底简报、教学中核实的资料摘要都沉淀于此，教学时优先读取（不从零摸底）。

## 模板

```md
---
source: https://example.com/original-article
credibility: A
verified: 2026-10-03
related: ["[[0001-xxx]]", "[[0003-yyy]]"]
---

# <资料标题>

## 摘要
2-3 句话概括这篇资料说了什么、对本工作区哪个知识点有用。

## 关键要点
- 要点 1（含具体数据/公式/结论）
- 要点 2
- 要点 3

## 与课程的关联
- 支撑 [[0001-xxx]] 的第 2 节（TCP 握手时序）
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| `source` | ✓ | 原文 URL；书籍则写 ISBN+页码 |
| `credibility` | ✓ | `A`（一手/官方规范/同行评审）、`B`（公认专家/权威社区）、`C`（单一来源，待交叉印证） |
| `verified` | ✓ | 最后核实日期（YYYY-MM-DD） |
| `related` | ✓ | wikilink 数组，关联到 lessons/ 的课程文件（不含扩展名） |

## 规则

- **A/B 要求 ≥2 个独立来源交叉印证**；只有单一来源时标 C——后续有新来源印证时升级并更新 `verified`。
- **课程引用资料时带上可信度**：如"据 [TCP 三次握手规范（A）](source-url)"——学习者一眼看出这条知识的置信度。
- **摘要不含未核实内容**：如果某要点没有来源支撑，在要点后标注"（未经核实）"。
- **宁缺毋滥**：每个知识点只存最优质的 1-2 条资料，不囤积——resources.md 管"全部可用来源"，library 管"已消化的最佳来源"。
- **时效敏感主题**：每 6 个月重查一次 A/B 级资料的 source URL 是否仍然有效，失效的降为 C 并标注"来源已失效"。
