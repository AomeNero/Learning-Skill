# mission.md 格式

`mission.md` 位于工作区的 `docs/` 子目录。它记录学习者学习这个主题的**原因**。每一个教学决策（接下来教什么、呈现哪些资源、设计什么练习）都应能回溯到这份文档。

**格式遵循 Obsidian Flavored Markdown**——创建与编辑时参照 `obsidian-markdown` 技能的语法约定（wikilink、tag、callout 等）。

## 模板

```md
---
title: "{主题}——学习使命"
tags:
  - "mission"
  - "{主题slug}"
created: 2026-10-03
status: active
---

# 使命：{主题}

## 为什么
{1–3 句话。学习者在追求的具体现实目标。掌握了这个技能，他们的生活或工作会有什么改变？避免"为了理解 X"这类抽象表述；追问底层结果。}

## 成功的样子
- {一件具体的、可观察的、学习者将能做到的事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、既有承诺、学习偏好——任何框定方法的东西}

## 范围之外
- {学习者明确表示现在不想追的相邻主题，保护最近发展区}
```

## YAML 字段

| 字段 | 说明 |
|------|------|
| `title` | Obsidian 属性面板显示标题 |
| `tags` | Obsidian 标签（`mission` + 主题 slug，支持嵌套如 `learning/mission`） |
| `created` | 创建日期 |
| `status` | `active`（进行中）/ `completed`（已完成）/ `superseded`（使命变更后标记） |

## 规则

- **一个工作区一个使命。** 学习者想学两个不相关的东西，那就是两个工作区。
- **具体压过抽象。** "十月底跑完半马"好过"变得更健康"。
- **对含糊其辞要追问。** 至多 2-3 轮；仍说不清就如实写"动机暂缺"并动笔。
- **现实变了就修订。** 使命变更时更新 `status: superseded`，并在新工作区重建。
- **保持简短。** 超过一屏就成了计划而不是罗盘。
- **创建与编辑时使用 `obsidian-markdown` 技能**——确保 YAML frontmatter、wikilink、tag 语法正确。
