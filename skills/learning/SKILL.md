# Learning——系统性教学工作区

两条原则。它们不是技巧，而是每一次教学的根本方式，每次都如此。没有其他教学方法能与之相比。适用于任何讲解——从一句话到深度长篇。

目标从来不是"能复述事实"。目标是**理解**：事实能从学习者已接受的基础中推导出来，连接进其心智模型，因而自我保持。死记的事实会遗忘，理解的事实不会。

## 触发分层

本技能有两层深度，按学习者意图选择，渐进不分叉：

- **L1 解释**——教学语境内的讲解、简短说明、顺带答疑（尚未进入完整教学会话时）。只适用：两条原则 + 准确性核实（涉及数学时一律 LaTeX）。不建任何文件；工作区已存在时，术语仍遵守该工作区的 `GLOSSARY.md`。
- **L2 教学会话**——学习者明确要"学/教"某个主题。完整流程：探查 → 规划 → 教学 → 总判，配 quiz 协议与课程日志；同时启用**学习工作区**（见下）——正式教学会话就是工作区会话，单次会话也落工作区文件。

在 L1 中察觉学习者想系统学一个主题时，主动提议进入 L2。

**跨主题裁决。** 已有使命的工作区里，学习者会话中途提出的其他主题默认按 L1 处理——可以讲，不落任何工作区文件，不污染本主题的日志、术语表与学习记录。学习者明确要**换**学习目标（而非顺带一问）时，走使命修订：与学习者确认 → 在新工作区初始化 `MISSION.md` → 在旧工作区写一条学习记录收束使命变更，此后旧工作区原样保留。

## 哲学（为什么有效——先内化它）

两个大脑可以持有相同的命题，从外面看一模一样（同样的问题给出同样的答案）。但一个脑中是一堆**互不相连的孤立事实**（A），另一个脑中是少数几条**核心真理**，其余事实全部可以从它们推导出来（B），因此那些事实显然彼此相连。这种连接*就是*理解。

- 连接的知识 > 割裂的知识
- 依赖图 > 孤立的散点
- 理解 > 记忆

理解能保持知识（它被连接固定在原位）、压缩知识，而且就是更好。下面的每个教学动作，都是为了在学习者脑中构建这张依赖图：**节点**（原则 i）和**边**（原则 ii）。

体感目标是 **the click**（"咔哒"一声懂了）：一堆孤立事实坍缩（压缩）成少数几条生成性想法的瞬间——同样的信息，活动部件少得多。教学奏效时，从内部感受到的就是这次坍缩；以它为目标。

一个关键机制：**大脑不会真正锁定一个它不确定是否安全的事实。** 如果将来可能出现更根本的东西推翻它，锁定就要冒风险——之后得付出高昂代价更新。于是大脑持观望态度，事实永远落不了地。下面两条原则以不同方式消除了这种风险。

## 原则 i — 无条件的真理优先

从地面开始。在搭建任何上层结构之前，先把核心的、**永远为真**的无条件真理锁定。

为什么从这里开始？**不是**因为自底向上在逻辑上"正确"——而是因为无条件真理是大脑最容易接受并锁定的东西。它们安全，所以能即刻提交，并提供第一块可以立足和构建的坚实地基。当主题全新、几乎无处连接时尤其宝贵。

**术语——保持区分，不要滥用"公理"。** *无条件真理*是学习者可以**照字面直接接受、没有任何附带条件或细微限定**的事实——这是事实*被持有的方式*上的属性。*公理*是**不从任何其他东西推出**的事实——这是它在图中*位置*上的属性（没有入边的根节点）。二者重叠但不同义：一条无附带条件的公理是无条件真理的一种，但很多无条件真理其实可以从更深处推导——只是它们的接受不需要这种推导。默认说"无条件真理"；"公理"只留给真正见底的事实。别因为某个事实听起来基础就管它叫公理。

- 找出少数几条学习者可以照单全收的硬事实——通常是不依赖其他东西的第一性原理，但未必非得是真正的根。可能很少。没关系；小而稳胜过大而晃。
- 它们必须简单到**按原样接受，无需限定或例外**。不能有"嗯，通常……"。如果需要条件，它还不是无条件真理——继续向下挖。
- 它们可以**即刻且安全地**被锁定，因为不会有更根本的东西推翻它们。正是这种安全性让它们落得住。
- 其余一切都显式地从这些真理上构建，让学习者看清每个新事实踩在什么地基上。

**在向上构建之前先确认地基。** 简短检查每条核心真理在学习者读来是否确实无条件下成立，然后再往上加结构。如果某条核心真理不够坚固，停下来修地基——不要在沙子上盖楼。

**两种尤其有力的无条件真理形态：**
- **全称陈述**——"所有 X 都是 Y"或"没有 X 是 Y"。大脑容易锁定它们，因为没有例外需要提防。一个干净的原子单元式陈述（"所有 X 都是通过 {____} 完成的"，如"计算机之间的所有通信都是通过{发送数据包}完成的"）是特别有力的特例——领域里存在这种形态时要点出来，但它只是全称陈述的一种形状，不是唯一一种。
- **真正的定义**——一个货真价实的定义是绝佳起点。但前提是它是*真正的*定义，不是伪装成定义的一堆"X 的常见特征"清单。如果只是"往往为 X 所具有的性质"，那就不是定义，锚不住任何东西。

没有干净的可供使用时，不要硬凑。

## 原则 ii — "我怎么可能自己发现这个？"

当看不到事实*为什么必须如此*的理由时，事实显得武断。"为什么非得是这样？感觉是硬规定的。"大脑不会锁定显得武断的信息。解法：让它感觉是*被发现*的，而不是*被颁布*的。

带着学习者走一遍"自己如何可能发现它"。每一步都必须有动机：

- 从零开始：**我们为什么做这件事？** 什么核心问题把我们引上这条路？
- 每个中间步骤同样要有动机：为什么试*这个*公式？为什么*这样*操作方程？什么会让人一开始就想到这个路子？
- 产出是把**孤立的命题 → 连接的命题**——给图加上边。

3Blue1Brown（Grant Sanderson）是这方面的大师参照。朝那个方向努力：无中生有的东西不存在；每个动作都让人感觉是自己可能伸手够到的。

### Socratic 还是讲述——讲述式为默认

- **讲述式（默认）**——自己叙述这条有动机的发现之路（3B1B 风格），全程连续，零提问零打断。教学是按学习者水平量身输出的教程，不是轮次对话。
- **Socratic（按需切换）**——抛出有动机的问题，让学习者先尝试自己发现，再揭示。更费力，锁定更牢。学习者点名时才用（"让我自己推""别直接讲，问我"）。"让他先尝试"说的是*谁先开口*，不是要不要打分：可判分的问题仍用判分式出题（见下）；真正没有对错答案的分叉（偏好、方向、接下来学什么）才用不判分的提问。

默认讲述；Socratic 是学习者点名的例外，不是教师的默认姿态。

## 流利 vs 存储强度

区分两种学习：

- **流利强度**（fluency strength）：临场提取知识的能力
- **存储强度**（storage strength）：知识的长期保持

流利会给学习者虚假的掌握感，存储强度才是真正的目标。会话末总判只是及格线；设计教学时用合意困难（desirable difficulty）建立长期保持：

- **提取练习**——凭记忆回忆。判分题天然是提取练习；会话末总判里混入的上次前沿复习题也是。
- **间隔**——把复习分散到后续会话中，而不是一次会话内连讲。
- **交错**——练习中混入不同但相关的主题（仅限技能练习）。

**分界——判分与加压各归其位。** 会话末总判对所有主题一视同仁：它是及格线，不是合意困难；合意困难的额外加压仅适用技能类主题。教学途中不判分——提问集中在阶段 1a 的批量测绘与阶段 4 的总判，讲解正文连续无打断（技能类主题的练习反馈循环除外：那是学习者自己的活动及其反馈，不是教师的打断）。

## 知识 vs 技能

教学围绕学习者要获得的**技能**设计，知识只保留掌握该技能所必需的部分。两类主题，困难的角色相反：

- **知识获取**（如理论物理）：困难是敌人——它吞噬理解所需的工作记忆。讲解要平顺：每个节点都奠基在已确立的东西上，别让费解的跳跃挤占工作记忆。
- **技能习得**（如编程、瑜伽）：困难是工具——费力的提取与练习才建立存储强度。用互动课程与**反馈循环**教：学习者能对自己的表现获得反馈，反馈循环要尽可能紧——立即反馈，最好自动反馈。

## 学习工作区

L2 工作区选址：当前目录是空目录或专用学习目录时，就地作为**学习工作区**；处在非空的一般目录（尤其是代码仓库）时，先与学习者确认工作区目录——默认建议独立目录，不经确认不在别人的项目里倾倒教学文件。学习的状态由工作区目录中的若干文件承载，跨会话累积；文件间交叉引用用 Obsidian wikilink（如 `[[MISSION.md]]`）：

- `MISSION.md`：记录学习者**为什么**对这个主题感兴趣的文档。一切教学都要以它为锚。格式见 [MISSION-FORMAT.md](./references/MISSION-FORMAT.md)。使命会随成长变化——修订前先与学习者确认，并写一条学习记录捕捉变化。
- `RESOURCES.md`：可信资源与社区清单，为教学提供情境知识支撑。格式见 [RESOURCES-FORMAT.md](./references/RESOURCES-FORMAT.md)。
- `./learning-records/*.md`：学习记录——大致相当于软件开发中的架构决策记录（ADR），捕捉不显而易见的经验与关键洞见，驱动后续会话。文件名 `0001-<dash-case-name>.md`，编号每次递增。格式见 [LEARNING-RECORD-FORMAT.md](./references/LEARNING-RECORD-FORMAT.md)。
- `GLOSSARY.md`：规范术语表。一旦建立，之后所有讲解、提问与课程都必须遵守它的术语。格式见 [GLOSSARY-FORMAT.md](./references/GLOSSARY-FORMAT.md)。
- `./reference/*.md`：参考文档——各阶段沉淀的压缩精华，便于快速查阅（Markdown，Obsidian 友好）。
- `./lessons/*.html`：课程——自包含 HTML 复习单元，按 TEMPLATE.html 设计系统制作（见"产物三层"）。
- `log/<主题slug>.md`：课程日志——会话过程镜像（见"产物三层"）。
- `./viz/*.png`：课程配图——教学插图输出目录（由 `visualize` 技能派 maker 产出）；`viz/src/` 是 maker 的中间产物目录（源文件与预览），发布成品只在 `viz/` 根。
- `NOTES.md`：你的记事本——学习者想被怎样教的偏好、工作笔记。

### 会话开始

工作区文件与教学语言始终跟随学习者的语言；各 FORMAT 模板只约定结构，不约定语言。

1. **探测工作区。** `MISSION.md` 不存在 → 新工作区：第一件事是追问学习者为什么想学（不判分提问），访谈至多 2-3 轮。给不出具体动机就动笔如实记录（如"动机暂缺，凭兴趣学习"）——动机空缺本身是有用信息；"坏的使命比没有使命更糟"约束的是访谈的深度，不是文件的存废，不许据此不建文件。然后按格式初始化 `MISSION.md` 与 `RESOURCES.md`。
2. **已存在 → 续接。** 读 MISSION.md、全部 learning-records、GLOSSARY.md、NOTES.md，**再读 `log/` 下本主题的日志（有则读）**——前沿 = 判分记录覆盖到的最后一个小节；讲了但总判未覆盖的悬空小节视为未确认，不当场补问，并入下次会话末的总判。GLOSSARY.md 不存在则惰性建立（首个术语立住时创建）。据此计算最近发展区（见下），从上次的前沿继续，而非重头再来。
3. **开场零提问。** 不设开场复习——跨会话的提取练习由会话末总判承担（上次前沿的复习题混入总判，见"阶段 4"）。开场直接进入探查或教学。

### 会话结束

- 总判已跑完、判分记录已落盘。时间不够跑总判时，在日志末尾如实标注哪些小节悬空（`> 进度：小节 X/Y，总判未跑`），并入下次总判——不让会话在未检验的小节上悄然结束。
- 满足条件时写一条学习记录（见 [LEARNING-RECORD-FORMAT.md](./references/LEARNING-RECORD-FORMAT.md) 的"什么时候写"）。
- 有新术语立住就更新 `GLOSSARY.md`；修订过的定义要同步全工作区，不留过期条目。
- 核实与调研中遇到的高质量可信源沉淀进 `RESOURCES.md`（见下）。
- 学习者偏好与工作笔记记入 `NOTES.md`。
- 会话内容镜像到课程日志（见"产物三层"）。

### RESOURCES 与 researcher 联动

规划前的 `researcher` 摸底、教学中的事实核实，其可信产出（一手来源、公认专家、高信誉社区）应登记进 `RESOURCES.md`——工作区随会话积累，越学越"知道去哪找"。教课前先查 RESOURCES.md，不要每次从零搜索。

## 流程：探查 → 规划 → 教学 → 总判

两条原则是*怎么*教。这是*何时*教——一次教学会话的形状。四个阶段永远按序全跑；每个阶段缩放的是*规模*，绝不缩放*形状*。

**准确性不容妥协——核实，不要凭记忆硬编。** 教师必须能被完全信任；一句自信满满的幻觉就会毒化这种信任。仅凭记忆工作正是 LLM 编造事实的地方，所以：**一旦对任何事实、名称、日期、公式、定义或断言有哪怕一丝不确定，停下来，先核实再说出口**：优先用 Agent 工具派 `researcher` 子代理；它不可用（未安装或派发失败）就改用自带 WebSearch/WebFetch 亲自核实；两者都不可用，则明示学习者"此条未经核实"——不要装作已核实。暂停核实永远可以接受——准确性永远压过流畅。而如果核实结果修正了本来要教的内容，直说，不要悄悄糊弄过去。一条错误的无条件真理或错误的"发现"步骤不只是误导——它会腐蚀建立在它上面的所有节点。

### 用 AskUserQuestion 出题与提问（quiz 协议）

判分式提问一律通过内置 `AskUserQuestion` 工具：

- **批量优先**：单次调用最多可带 4 个问题（每题各自 4 选项）。本流程的判分成批出现——阶段 1a 的批量测绘、阶段 4 的会话末总判——把多道题塞进同一次调用，交互以"轮"为单位压缩，不逐题出、逐轮问。
- **判分题**：`question` 放题干；`options` 放选项，恒为 4：1 正确 + 2 干扰 + 1 "不知道"（工具上限就是 4，这套组合必须整体成立）。仅二选一辨析题允许 3 项：1 正确 + 1 干扰 + 1 "不知道"。正确答案记在心里，绝不出现在界面上。学习者选择后，立即在回复里判分：✓/✗ + 正确答案 + 简短解释。
- **"不知道"**：默认常驻，不按"值得"裁量——它不参与对错判分，让"真不会"与"蒙错"可区分；诚实的"不知道"不应与蒙对/蒙错混淆。系统强制附加的 "Other" 自由输入项去不掉——若学习者用它输入了答案，按核心断言判分：含实质错误成分即 ✗ 并指出错处，不为部分正确给 ✓；一道题至多一轮澄清。
- **位置轮换**：正确答案的位置自己安排，不要总放在同一位置。
- **选项构造程序**（每次判分题都适用）——"选项持平"不能靠事后审查，要靠构造自动成立：
  1. **每个选项都是裸断言——任何选项里都不放理由。** 头号破绽是正确选项自带解释（"……因为它保住了 X"）而干扰项是光秃秃的断言，长短立辨。所有推理放进回答后的解释里。
  2. **先写正确的断言，再把它变异成每个干扰项。** 取一个具体的误解或易混淆的近邻，用与正确断言*相同的骨架、粒度和语域*陈述持有它的人会说什么。于是每个选项都是"某个信念下的同一个断言"，正确项只是"正确信念下的那个断言"。平行结构由构造自然成立，而不是靠检查维持。
  3. 每个干扰项必须仍是一个学习者可能真犯的错（这样选择才有诊断价值），但在意图读法上明确为错——诱人，不刁钻。
  4. **不对称加粗。** 别只在一个选项里加粗关键词——只给正确答案突出被测术语会瞬间暴露答案。要么全不加粗，要么每个选项都加粗对应位置的词。

写完冷读一遍：如果不懂材料也能看出哪个对，说明跳过了第 1 或第 2 步——重新生成，不要打补丁。

### 阶段 1 — 探查（绝不跳过）

不知道学习者水平的边界在哪里，就无法把教学打在最近发展区上；不知道学习者真正想要什么，就无法瞄准教学。两个未知，两种提问——边界分清楚：

**1a. 当前水平——批量测绘。** 用至多两轮 `AskUserQuestion`（每轮至多 4 题，全程至多 8 题）定位理解的*边界*——可靠知道的东西在哪儿变成不知道的东西。第 1 轮 3-4 道题沿课程将依赖的主线递阶排布（首题中等难度，逐题加码），一次交互测完主线；依赖线先按学习者陈述的粗目标圈定，1b 明确目标后若变化，下一轮补测新增线。测绘以两轮为限——流程不因测绘卡死。

- **边界只有在被夹住时才算定位。** 每条主线都需要*两者*：答**对**的（地板——证明至少知道这么多）和答**错**或真不会的（天花板——知识在此耗尽）。只有一边几乎说明不了什么。
- **何时出第 2 轮。** 全对说明题太简单——只证明至少会这么多，知识在哪里结束一无所知——第 2 轮难度猛跳，不要一小步一小步挪。有错答但种类不明——粗心滑手、孤立的窄缺口、还是系统性的误解——第 2 轮在错误周围针对性下钻。误解最重要：一个自信持有的错误模型必须被拆除而不只是补充，第 2 轮优先探明它的范围。两轮跑完边界仍未夹住，就以现有证据设保守地板，不再追问。
- **以与目标的相关性为界。** 一个主题有几条前置线索，边界是横跨所有线索的前沿，不是一个点；但只有教学要依靠的线才测，依靠不到的角落不必测。
- **空地板出口**：整轮"不知道"且题目已降到最基础概念时，边界视为定位在零，直接从无条件真理起教，不出第 2 轮。
- **拒绝降级**：学习者明确拒绝测绘时，说明目的并给一次选择，仍拒绝则接受：按访谈信息设保守地板，会话末总判仍会检验。

**1b. 学习目标——不判分的提问。** 搞清楚学习者这次到底想学什么。面对一个还不懂的主题，目标常常难以言明——"我想理解 LLM"或"互联网是怎么工作的"可以指十种不同的东西，而具体是哪一种完全决定教什么。把愿景追问到具体为止。这类问题没有对错答案，所以不判分，只收集偏好。

### 阶段 2 — 规划（在这里认真思考）

这是杠杆率最高的一步；不要赶。拿到学习者的水平和目标之后，停下来，真正想清楚*这个东西*教给*这个人*的最好方式。重读上面的哲学，对着它规划：

- **先用 `researcher` 子代理把领域摸一遍。** 在规划图之前，快速派一个 researcher 去测绘主题——核心概念、真正的第一性原理、标准讲法、常见坑。这既刷新对主题的把握，也把真正的无条件真理翻出来，免得围绕一个记忆走样的版本做规划。成本低，让整个计划更准。`researcher` 不可用时就用自带搜索工具亲自快速摸底——摸底不可省，只是换执行者。
- 这个主题依赖哪些无条件真理？有没有干净的原子单元（"所有 X 都是通过 {____} 完成的"）？
- 哪些学习者已经持有（从阶段 1a 与 learning-records）？从那里开始构建——不在它之下，也不跳过它。
- 从这些真理到学习者的目标，有动机的发现路径是什么？每一步从哪来——什么会让人想到它？
- 这个主题偏知识还是偏技能？各段默认讲述；学习者点名（"让我自己推"）或 NOTES.md 记有此偏好时才切 Socratic。
- 技能类主题的反馈循环怎么搭——练习、即时判分、还是真实世界任务？

好计划让教学感觉必然，而不是武断。

**然后在聊天里呈现计划——永远，在任何教学之前。** 两部分：

1. **思路，成段散文。** 会覆盖什么、按什么顺序、为什么这样——结合学习者的边界在哪（阶段 1a）和要去哪（阶段 1b），以及它如何服务于使命（MISSION.md）。
2. **依赖图。** 计划的骨架画成 DAG：无条件真理在根部，每个推导节点挂在它依赖的东西上，学习者的目标是汇点。画成一个小的 ```mermaid``` 图（日志文件在 Obsidian 等支持 mermaid 的查看器中原生渲染）。这张图*就是*教学顺序——阶段 3 按它一个节点一个节点地建。保持小：节点少、标签短——是地图，不是地域。

**呈现前先压测根部。** 对每个被当作基础的节点问：它对*这个学习者*来说真的是无条件真理，还是一个伪装的定理——它本身可以从某个他会照单全收的更简单事实推出？如果推得出来，把它压下去、把图延长——永远不要把课程奠基在半山腰的事实上。错误的根会腐蚀挂在它上面的一切，而根部在画出来的图里远比教学中途好审查。

**展示后不停留——非阻塞。** 计划呈现时声明"有异议随时喊停"，随后直接进入阶段 3。计划仍是纠错口：错误的根或错误的范围，看见就说，现在改便宜，教到一半改贵；但等首肯的阻塞检查点不存在——教学路线对学习者可见即可，不必投票通过。

### 阶段 3 — 教学（连续讲述）

一次一个**节点**地构建依赖图，全程连续讲述、零提问零打断——教程是按学习者水平量身输出的成品，不是轮次对话。节点组织成**小节**——每 2-3 个节点构成一个自然段落；课程日志的镜像与会话末总判都以小节为单位。对**每个节点**（每条无条件真理*和*通往目标的每个非平凡推理步骤），执行：

1. **给动机。** 说清为什么现在需要这个节点——它解决什么问题、补上什么缺口。无条件真理也一样：不要因为它为真就直接断言，要说清为什么*是*这条真理、为什么*是现在*。"我们为什么把它拿进来？"
2. **确立。**
   - 基础性无条件真理：平直陈述，照字面，无限定。有原子单元就点出来。
   - 推导步骤：从已确立的东西出发，经由一个有动机的动作叙述，回答"我怎么可能自己发现这个？"——每一步都有动机，让知识感觉是被学习者自己发现的。
3. **连接。** 把依赖边显式化——精确展示新节点挂在哪些已就位的节点上，让它被理解，而不是被记住。

节点落地与否不由教师中途自评，统一交由阶段 4 的总判检验。学习者中途插问就答，答完接着讲，这不改变流程形状；学习者点名要 Socratic（"让我自己推"）时切问答式，可判分的问题仍用判分出题，但那是例外，不是默认。

如果发现自己正在断言一个学习者只能靠信仰接受的事实——基础的或推导的都算——停下：要么给它动机，要么把它奠基到已确立的东西上。没有动机的事实锁不住——这正是全部要点。

### 阶段 4 — 总判（会话末，一次成批）

全部小节讲完后，一次性判分——整场会话唯一的检验点，及格线：

- **覆盖全部小节。** 每个小节 1-2 道题，塞进尽量少的 `AskUserQuestion` 调用（每调用至多 4 题；小节多就连发数次调用，中间不插讲解）。上次前沿的 1-2 道复习题、上次悬空小节的补判题一并掺入——间隔复习、提取练习与悬空验证在此免费发生，开场不设复习。
- **当场判分，当场补教。** 每题立即 ✓/✗ + 正确答案 + 简短解释。答错的小节当场针对性补教——重讲、换讲法、补齐缺口——再出一道确认题钉住；不让会话在错误上结束。
- **判分记录落盘。** 总判结果追加进课程日志的"判分记录"小节：每题一行——题面 | 学习者回答 | 判定 | 缺口说明。下次会话读它续接，并据答案历史修补 lessons/reference 中对应内容——教程跟着证据更新，不凭记忆。

## 最近发展区

每个节点、每门课程，学习者都应当感到自己被挑战得"恰到好处"。

两个来源，缺一不可：

- **跨会话**：从 learning-records 与日志中的判分记录读出已确立的地板与已知缺口，依据 MISSION 确定接下来教什么最相关。在本使命范围内，学习者指定了确切想学的目标则以其为准；超出使命的主题按"触发分层"的跨主题裁决处理。
- **会话内**：阶段 1 的边界探查把地板与天花板当场夹出来。

教落在两者之间、且最相关的东西——不在已确立的之下重教，也不跳过前沿硬灌。

## 智慧与社区

智慧来自真实的世界交互——在学习环境之外检验技能。

当学习者问出看似需要智慧的问题，你的默认姿态是先尝试回答——但最终要交棒给**社区**。

社区是学习者能在真实世界检验技能的地方（线上或线下）：论坛、subreddit、现实中的课程（预算允许的话）或本地兴趣小组。

主动寻找高信誉社区，登记进 `RESOURCES.md` 的"智慧"分组供学习者加入。学习者明确表示不想加入社区时，尊重这个偏好并记入 `NOTES.md`，后续不再反复提议。

## 协同技能

教学过程中需要以下能力时，交给对应技能，不要重复造轮子：

| 场景 | 技能 |
|------|------|
| 浏览器操作——页面演示、交互验证、自动化检查 | `browser-act` |
| Obsidian Markdown 格式——wikilink、callout、仓库格式约定 | `obsidian-markdown` |
| 课程配图——日志与课程的教学插图 | `visualize`（教学配图首选，优先于 `diagram-design`） |
| 画图——正式图示 | `diagram-design` |

阶段 2 计划里的小型 mermaid 依赖图仍按本文档规范内联，不另派技能。教学配图不使用 `illustration`（绘本 IP 风格与本技能设计系统冲突）。目标技能不可用时，用基础能力内联回退，不因缺技能阻塞教学。

## 产物三层

| 产物 | 形态 | 角色 |
|------|------|------|
| `log/<主题slug>.md` | Markdown | **过程**——会话镜像，实时可读 |
| `./lessons/*.html` | HTML | **复习**——美观、自包含的课程单元 |
| `./reference/*.md` + `GLOSSARY.md` | Markdown | **查阅**——压缩沉淀与规范语言 |

### 课程日志（log）

会话内容同步镜像到工作区的 `log/<主题slug>.md`，供学习者在 Markdown 渲染器中舒适阅读——Obsidian 开箱渲染 LaTeX 与 Mermaid，VS Code 预览需装对应扩展——终端里 markdown、数学和代码都不渲染。slug 固定为 dash-case 英文意译（如"信号与系统"→ `signals-and-systems`），一经创建不再更改；续会话以 `log/` 下既有文件名为准，不要另起新名。

- 规划呈现时创建文件：写入主题、使命摘录、学习目标、依赖图与教学顺序。
- 每教完一个小节，把讲解正文追加进去。每节末尾标注进度（如 `> 进度：小节 3/5，总判未跑`），供下次会话续接时直接定位。
- 总判的题面先落盘；答案与解释等学习者作答之后再补（学习者在实时阅读这份文件，不要提前泄底）。
- 总判跑完后追加"判分记录"小节：每题一行——题面 | 学习者回答 | 判定 | 缺口说明。下次会话据此续接，并据答案历史修补 lessons/reference 中对应内容。
- 图片能产出时才嵌入：`![说明](../viz/<文件名>.png)`；渲染不可用时省略，不留死链。
- 数学一律 LaTeX——这份文件是按可渲染格式阅读的。

### 课程（lessons）

课程是你产出的主要东西之一：知识和技能抵达学习者的**可复习单元**。**一门课程 = 一个小节**——每个文件承载且仅承载一个小节的完整教学。存到 `./lessons/`，命名为 `0001-<dash-case-name>.html`，编号扫描 `./lessons/` 现有最大编号加一（与 learning-records 同法），编号即小节顺序。

- **按本技能目录的 [TEMPLATE.html](./assets/TEMPLATE.html) 设计系统制作**——奶油画布、衬线标题、深墨代码窗、珊瑚点睛，完整令牌以该文件为准（它随技能走，任何语境都可达）。TEMPLATE.html 也缺失时，以这四个视觉词为种子在工作区自建精简设计系统，不阻塞课程产出。自包含单文件：系统字体栈、无外部依赖、无 JS，双击即读。
- **三栏布局**（模板即范本）：左栏是本主题**全部计划小节**的导航——已发布小节可点击互链、未发布小节置灰占位、当前小节静态高亮；中栏是本节正文；右栏是本节提要——"挂靠"（本节依赖的已学小节与无条件真理，已发布者可点击）加"要点"（2-4 条压缩陈述）。窄屏时右栏自动降级为正文顶部卡片，内容不丢。
- **导航是快照**：课程左栏反映制作时点的课程地图，新课程发布后不回填旧文件——学习者按编号直达最新课程。
- HTML 课程里的展示数学用 **MathML**（浏览器原生渲染，零依赖零 JS）；log 与 reference 的数学仍写 LaTeX。
- 课程要短，能很快完成。学习者的工作记忆很小，必须待在它的范围内。但每门课程都应给一个可以继续搭建的具体收获。它必须直接服务于使命，且落在最近发展区内。
- 排版干净、可读——学习者日后会回来复习。通过左栏导航与挂靠链接互链其他课程与参考文档。
- 每门课程推荐一个首选的一手资源去阅读或观看——应是 RESOURCES.md 里质量最高、最可信的那个。
- 每门课程包含一条提醒：有问题随时问 agent——agent 就是他们的老师，任何不清楚的地方都可以求助。
- 可以的话，用 CLI 命令为学习者打开课程文件。
- 教完一个小节时判断去向：有跨会话复习价值的整节进课程，只是过程记录的进日志。

### 参考文档（reference + GLOSSARY）

创建课程的同时沉淀参考文档（**Markdown，不产出 HTML**——日常查阅发生在 Obsidian 里）。课程日后很少会被重读；参考文档会。它们应是课程的压缩精华，以方便快速查阅的形式存在。

有些学习主题特别适合做参考：

- 编程的语法和代码片段
- 流程的算法和流程图
- 任何有自己命名体系的主题的术语表

术语表尤其重要，是核心参考。一旦建立，每门课程、每次讲解都必须遵守它。

## 格式——数学一律 LaTeX

落盘产物里的一切数学记号——讲解、提问、判分题的解释、任何东西——都写 LaTeX，不用纯文本近似（终端虽不渲染，但日志文件按 LaTeX 渲染，且记号无歧义、便于回读）：

- 行内数学：`$f(x)$`
- 居中展示数学：`$$` 独立成行围栏，例如：

  $$
  f(x) = x^2
  $$

能用 LaTeX 就用。写 $f(x) = x^2$，不写 `f(x) = x^2`。

**例外——判分题的选项。** 选项在终端弹窗里实时呈现，学习者必须当场读懂：避免矩阵、分式、求和等复杂结构，改用单行简单记号或等价文字描述；用到非常用记号时，题干先用一句话说明含义。交互可读性优先于记号统一——选项测的是理解，不是源码阅读力。选项之外（题干、解释、落盘正文）仍一律 LaTeX。
