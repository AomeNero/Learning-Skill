# Learning Skill 介绍——系统性教学工作区全景

> 一套面向 Claude Code 的中文教学系统：把一个主题**教到真正被理解**——事实能从已接受的地基硎中推导出来、连接进心智模型——而不是死记硬背。核心理念：**理解 > 记忆**，教学的一切动作都是为了让学习者的脑中长出一张**依赖图**（少数核心真理在根部，其余事实挂在上面推导得出）。

本文回答三个问题：**这套系统的流程是什么样子的**、**它会在什么阶段生成哪些文档**、**每个文档长什么样、承担什么角色**。

## 2. 设计哲学（系统为什么这样教）

- **连接的知识 > 割裂的知识**：两个脑可以持有同样的命题，一个是孤立散点，一个是少数核心真理加推导——后者才是理解。教学的目标体感是 **the click**：一堆孤立事实坍缩成几条生成性想法的瞬间。
- **原则 i——无条件的真理优先**：先锁定少数几条可照字面接受、无附带条件、不会被更根本的东西推翻的硬事实，其余一切显式地构建在它们之上。术语上区分*无条件真理*（持有方式上的属性）与*公理*（图中无入边的根节点），不滥用"公理"。
- **原则 ii——"我怎么可能自己发现这个？"**：显得武断的事实锁不住。每个事实都带着动机走一遍发现之路——为什么做这件事、为什么试这个方法、什么会让人想到这条路。**讲述式是唯一教学形态**（3Blue1Brown 风格连续叙述，零打断）；检验不在讲解中途，而在每个小节末的考核。
- **零基础默认**：不做水平测绘——地板定在零，从无条件真理起教；口头声明的既有知识可作起点参考，误解暴露时当场纠正。
- **流利强度 vs 存储强度**：临场流利会给虚假的掌握感，长期保持才是目标。小节末考核只是及格线；错题驱动机制（落档 → 下次融入重教 → 确认题划销）承担间隔复习与提取练习。
- **知识 vs 技能**：知识类主题（如理论物理）困难是敌人，讲平顺；技能类主题（如编程）困难是工具，用反馈循环教——反馈越紧越好。
- **最近发展区**：教"地板之上、目标之下、且最相关"的东西——地板由考核结果只上移不下压，无证据时从无条件真理教起。

## 3. 触发分层

| 层 | 触发 | 行为 |
|----|------|------|
| **L1 解释** | 教学语境内的顺带讲解、答疑 | 只用两条原则 + 准确性核实，**不落任何文件** |
| **L2 教学会话** | "我想学 X""系统性学习 X""教我 X" | 完整三阶段流程 + 学习工作区全部产物 |

已有使命的工作区里，会话中途冒出的其他主题默认按 L1 处理（不污染本主题文件）；明确要**换**学习目标时走使命修订——新工作区初始化 `docs/mission.md`，旧工作区写一条学习记录收束后原样保留。使命内的方向优化是后续追加项：`docs/answer.md` 中反复出现的错题模式是优化学习方向的天然信号。

## 4. 完整流程：目标访谈 → 规划 → 教学（小节末考核）

三个阶段**永远按序全跑**；每个阶段缩放的是*规模*，绝不缩放*形状*。

```mermaid
flowchart TD
    A[会话开始：探测工作区] -->|docs/mission.md 不存在| B[使命访谈 至多2-3轮<br>初始化 docs/mission.md + resources.md]
    A -->|已存在| C[读 docs/ 状态 + 扫描 lessons/<br>定位上次前沿]
    B --> D
    C --> D["阶段1 目标访谈（不判分）<br>把愿景追到具体；零基础默认"]
    D --> E["阶段2 规划：researcher 摸底<br>→ 依赖图（压测根部）→ 呈现计划"]
    E --> F[计划只在对话呈现]
    F --> G["阶段3 教学：逐节点连续讲述<br>（动机 → 确立 → 连接）"]
    G -->|每教完一小节| H["产出课程 + question.html 考核页<br>学习者浏览器作答、点击提交自判分<br>作答报告贴回，落 docs/answer.md"]
    H --> I{还有小节？}
    I -->|是| G
    I -->|否| J["会话结束：resources 沉淀 /<br>考核报告回收落档 answer.md"]
    J --> K([会话结束])
    C -.错题驱动：answer.md 未清错题.-> G
```

### 会话开始——探测工作区（三选一）

- **新工作区**：`docs/mission.md` 不存在（大小写不敏感匹配，`MISSION.md` 等旧名视为同一文件）→ 第一件事追问学习者为什么学（不判分访谈，至多 2-3 轮；给不出动机就如实写"动机暂缺"），随后初始化 `docs/mission.md` 与 `docs/resources.md`。工作区选址：空目录或专用学习目录就地使用；在代码仓库里触发则先确认目录，不往别人项目里倾倒文件。
- **续接**：读 `docs/` 下的 mission.md、resources.md、answer.md（有则读），扫描 `lessons/` 目录——课程即已讲，考核档案即已考：课程存在即已讲，answer.md 有其考核记录即已考。前沿 = 最后一个已考课程；考核文件在而档案无记录 = 悬空，下次优先补考；教学计划读最新课程左栏。**错题驱动**：answer.md 未划销错题所涉知识点在教学顺序中优先安排重教。
- **开场零提问**：不设开场复习——跨会话提取练习由错题驱动机制承担，开场直接进入目标访谈或教学。

### 阶段 1——学习目标（不判分的提问）

**教学对象默认零基础**：不测绘、不摸底考，从无条件真理起教；口头声明的既有知识可作起点参考。误解不预设，暴露时当场纠正。

把愿景追问到具体为止——"我想理解 LLM"可以指十种东西，具体是哪一种完全决定教什么。只收集偏好，无对错。

### 阶段 2——规划（杠杆率最高的一步）

1. 先派 `researcher` 子代理摸底领域（核心概念、真正的第一性原理、常见坑）——摸底不可省，只换执行者。
2. 对着哲学设计依赖图：无条件真理、错题重教需求（answer.md）、有动机的发现路径、知识/技能定性。
3. **压测根部**：每个当作基础的节点问"它真是无条件真理，还是伪装的定理"——推得出来就压下去。
4. 呈现计划：一段散文思路 + 一张小型 mermaid 依赖图。**展示后不停留**——声明"有异议随时喊停"后直接开教，无阻塞审批点。

### 阶段 3——教学（连续讲述 + 小节末考核）

一次一个**节点**构建依赖图（给动机 → 确立 → 连接）；每 2-3 个节点构成一个**小节**。每讲完一个小节：

- **小节末考核**：生成本节课程 HTML（正文 + 末尾"小节考核"区，≤4 道判分题，A/B/C/D 选项、答案不预写）；学习者学完课程回到对话作答（如 `1.A 2.B 3.不知道 4.C`），逐题当场判分（✓/✗ + 正确答案 + 简短解释），答案与解析随即补进课程。
- **答错只记录、不回头**：错题（题面 | 错答 | 正确答案 | 所属小节 | 日期）追加进 `docs/answer.md`，作答完毕继续推进——补教由下次会话的错题驱动机制承担，本次会话保持节奏。
- **错题重教**（续接会话）：教学顺序中优先重教 answer.md 未划销错题所涉知识点——换讲法、补动机——重教后出一道确认题（AskUserQuestion 判分）钉住，答对划销该条（保留可见，标记已清除）。

### 会话结束——落盘清单

- 已讲小节的考核已跑完、错题已落 `docs/answer.md`；时间不够时如实标注悬空小节，并入下次补考；
- 高质量可信源沉淀进 docs/resources.md。

## 5. 生成的文档全景（核心）

### 5.1 总表——什么阶段生成什么

工作区布局分两处：**`docs/` 子目录收纳状态管理文件**；教学产物（lessons/）留在工作区根。**所有文件一律小写英文命名**。

| 文档 | 形态 | 首次生成时机 | 后续更新节奏 | 角色 |
|------|------|--------------|--------------|------|
| `docs/mission.md` | Markdown | **会话开始**：使命访谈（≤2-3 轮）后初始化 | 使命修订时（先与学习者确认；错题模式可作信号）；换目标时在新工作区重建 | 锚——一切教学决策回溯到它 |
| `docs/resources.md` | Markdown | **会话开始**：与 mission 一起初始化 | 规划摸底、教学中核实的可信产出随时登记；会话末统一沉淀 | 情境知识支撑——越学越"知道去哪找" |
| `lessons/000N-*.html` + `000N-*-question.html` | HTML（三栏课程页 + 配对考核页） | **阶段 3**：每讲完一个小节即产出两个配对文件 | **快照不回填**；考核页提交后报告落 answer.md | 复习单元 + 考核载体 |
| `docs/answer.md` | Markdown | **阶段 3**：首次答错落档时创建 | 每次小节考核答错即追加；重教通过确认题后划销（保留可见） | 错题档案——驱动重教与方向优化 |
| `lessons/*.png` | PNG | **阶段 3**：教学配图需要时（派 diagram-maker） | — | 课程插图（`lessons/src/` 为 maker 中间产物） |

### 5.2 工作区目录树（成熟期形态）

```

│   ├── mission.md               # 为什么学——锚
│   ├── resources.md             # 可信资源与社区
│   └── answer.md                # 考核与错题档案——已考证据 + 重教驱动
└── lessons/
    ├── 0001-a-journey-of-a-message.html   # 一门课程 = 一个小节
    ├── 0001-a-journey-of-a-message-question.html   # 配对考核页
    ├── 0002-packets-the-atom.html
    ├── 0002-packets-the-atom-question.html
    ├── 0003-ip-best-effort.html
    ├── <slug>-<timestamp>.png    # 课程配图（maker 发布成品）
    └── src/                      # maker 的源文件与预览（中间产物）
```

### 5.3 各文档详述

#### docs/mission.md——学习使命

记录学习者**为什么**对这个主题感兴趣，一切教学以它为锚。结构：`为什么`（1-3 句具体现实目标）→ `成功的样子`（具体的、可观察到的事）→ `约束` → `范围之外`。规则：一个工作区一个使命；具体压过抽象；保持简短——超过一屏就成了计划而不是罗盘。

#### docs/resources.md——可信资源清单

策展的高可信来源集合，分 `知识` 与 `智慧（社区）` 两组。规则：每条必须注释（覆盖什么、何时该用）；显式标出缺口驱动未来搜索；无情修剪——五个锋利的来源好过三十个平庸的；学习者拒绝社区时在本文件末尾记一行备注。

#### docs/answer.md——错题档案

每次小节考核一条记录：`## <课程基名> · <日期> · <对>/<总>`，其下逐条列错题（题面 | 我答 | 正确答案 | 缺口说明），全对也记一条（已考证据）。数据来源是考核页提交后生成的**作答报告**（学习者贴回对话，教师按格式落档、不重判）。三条生命线：**落档** → **重教**（未划销错题融入教学流优先重教，重教后出确认题）→ **划销**（答对确认题即标记已清除，保留可见）。反复出现的错题模式是使命与方向优化的天然信号（后续追加项）。

#### lessons/*.html——课程（复习单元）

**一门课程 = 一个小节**，命名 `0001-<dash-case-name>.html`，编号即小节顺序，每讲完一个小节即产出。按 `template.html` 设计系统制作，自包含单文件：系统字体栈 + 内嵌 KaTeX（样式、base64 字体、脚本制作时全部内联），无外部网络依赖，离线双击即读。三栏布局：左栏 = 全部计划小节导航（已发布可点/未发布置灰/当前高亮，快照不回填）；中栏 = 本节正文；右栏 = 本节大纲（页内锚点快速定位）。数学写 LaTeX（行内 `$x$`、独立 `$$…$$`），由内嵌 KaTeX 渲染。每门课程推荐一个首选一手资源，并包含"有问题随时问 agent"的提醒。课程配图（`*.png`）与课程同目录。**考核不在课程内**——配对的 `000N-<slug>-question.html`（按 question-template.html 制作）：单选作答、点击提交页内自判分并生成作答报告（复制/下载），报告贴回对话后落 answer.md。

## 7. quiz 协议（AskUserQuestion 出题规则）

判分式考核两种载体：**小节考核**（配对 question.html：单选作答、提交后页内自判分并生成作答报告，报告贴回对话落 answer.md）与**确认题**（错题重教后，`AskUserQuestion` 单题）。共同规则：

- 选项恒为 4：1 正确 + 2 干扰 + 1 "不知道"（"不知道"不参与对错判分，让"真不会"与"蒙错"可区分）；
- 正确答案位置轮换；**选项都是裸断言**（推理放判分后的解释里）；先写正确断言再变异出干扰项——同骨架、同粒度、同语域；干扰项必须是学习者可能真犯的错；加粗要么全有要么全无；
- 对话里的自然语言作答按核心断言判分：含实质错误即 ✗ 并指出错处。

---

## 8. 准确性纪律

教师必须能被完全信任——一句自信的幻觉就会毒化它。**对任何事实、名称、日期、公式有一丝不确定，先核实再说出口**：优先派 `researcher` 子代理；不可用则自带 WebSearch/WebFetch 亲自核实；两者都不可用则明示"此条未经核实"。核实结果修正了本来要教的内容时直说，不悄悄糊弄。可信产出随会话沉淀进 `docs/resources.md`。

## 9. 协同技能与子代理
